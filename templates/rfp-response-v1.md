# RFP Response Template · v1

> ⚠️ **Teaching template.** Reusable structure with fictional placeholders. Adapt to each
> RFP's actual required format — **the issuing agency's structure always overrides this
> one.** See [BIZ-DEV.md](../playbooks/BIZ-DEV.md).

**Version:** 1.0 · **Owner:** BD Director · **Review:** annually

---

## How to use this

1. **Read the RFP's required structure first.** If it prescribes a format, use theirs. A
   non-conforming response can be excluded before it is read.
2. Build the **compliance matrix** (§A) before writing anything. This is not optional.
3. Draft sections in parallel — they are independent.
4. Verify against §Z before submission.

**Delete every `[PLACEHOLDER]` and every instruction block before submitting.** Search the
final document for `[` — it catches both.

## §A · Compliance matrix *(internal — do not submit)*

**Build this first.** One row per RFP requirement. It is the highest-value artefact in the
bid and doubles as a mechanical verifier: *is every row addressed?*

| Req # | RFP reference | Requirement | Mandatory? | Response location | Evidence | Owner | Status |
|-------|---------------|-------------|-----------|-------------------|----------|-------|--------|
| 1 | §2.1 | _[requirement verbatim]_ | Y | §3.2 | _[proof]_ | _[ ]_ | ⚪ |
| 2 | §2.2 | | | | | | |

**Status:** ⚪ Not started · 🟡 Drafted · 🔵 Reviewed · 🟢 Complete

> 🚫 **Any mandatory requirement not addressed is a disqualification.** Check this matrix is
> 100% green before §Z. This single check prevents the most common and most avoidable way
> to lose a bid.

---

## §B · Win themes *(internal — do not submit)*

Three to four. Each must be **specific, evidenced, and difficult for a competitor to
claim.**

| # | Win theme | Evidence | Where it appears |
|---|-----------|----------|------------------|
| 1 | _[e.g. "Only bidder with cleared personnel already deployed on comparable programmes"]_ | _[specific past delivery]_ | §1, §3.1, §5 |
| 2 | | | |
| 3 | | | |

**Test each one:** could a competitor write the same sentence? If yes, it is not a win
theme — it is boilerplate. "We are experienced and reliable" is what every losing bid says.

## 7 · Compliance, security and data protection

> **Guidance:** Increasingly a scored section rather than a formality — particularly for
> public-sector work, where **AI Verify and ISAGO are being embedded into procurement
> standards.** Treat it as a differentiator, not a box to tick.

### 7.1 Data protection
_[PDPA compliance. Data classification. Retention. Cross-border position. DPO.]_

### 7.2 Information security
_[Access control, encryption, incident response, certifications.]_

### 7.3 Personnel security
_[Clearance, background checks, confidentiality undertakings, offboarding.]_

### 7.4 AI governance
_[If AI is used in delivery, state it plainly:]_

- Where AI is used, and where it is not
- Human oversight — **a named human owns every output**
- Data handling: no client or personal data in unapproved tools; redaction before
  processing
- Audit trail: versioned artefacts, approval history
- Alignment with IMDA's Model AI Governance Framework and AI Verify principles
  (transparency, explainability, fairness, safety, accountability)

> **Say it explicitly rather than hoping nobody asks.** Evaluators increasingly do ask, and
> a clear, honest AI governance position is a differentiator against bidders who are vague
> about it. See [COMPLIANCE.md §9](../compliance/COMPLIANCE.md#9-imda--public-sector-delivery).

### 7.5 Business continuity
_[Continuity plan, key-person risk, disaster recovery.]_

## §Z · Pre-submission verification *(internal)*

### Mechanical checks — automate these

- [ ] **Compliance matrix 100% complete** — every mandatory requirement addressed
- [ ] **Pricing arithmetic verified** — all tables sum correctly
- [ ] **Every rate matches the approved card**
- [ ] **No `[PLACEHOLDER]` text remains** — search for `[`
- [ ] **No tracked changes or comments**
- [ ] Page/word limits respected
- [ ] File naming per RFP instruction
- [ ] All mandatory forms present and signed
- [ ] **No PII beyond agreed personnel details**

### Judgement checks — human required

- [ ] Win themes clear and evidenced
- [ ] Every claim traceable to a real engagement
- [ ] Reads as answering *their* question, not describing us
- [ ] **Self-scored against the published evaluation criteria**
- [ ] Compliance review complete 🚪
- [ ] Quality review by someone not involved in drafting 🚪
- [ ] Final approval recorded 🚪

### Submission

- [ ] Portal tested **before** deadline
- [ ] Submitted with time in hand
- [ ] Receipt saved
- [ ] Logged in [audit-logs.md](../projects-imda/audit-logs.md)
